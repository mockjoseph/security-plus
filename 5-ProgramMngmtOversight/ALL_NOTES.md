# 5.0 Security Program Management and Oversight

### Table of Contents


### 5.1 - Security Policies
**<u>Guidelines</u>**
- What rules following to provide CIA (confidentiality Integrity Availability)
- High level strategies
    - Data storage requirements, security event procedures
- Detailed security goals
    - Wi-fi usage, requests for remote access
- Security policies answer the "what" and "why"

**<u>Information Security Policies</u>**
- Big list of all security related policies
    - Centralized resource for processes
- Compliance requirements
- Detailed security procedures
- List of roles and responsibilities
- Just words and letters

**<u>Acceptable Use Policies (AUP)</u>**
- What is acceptable use of company assets?
    - Detailed documentation
    - May be documented in the Rules of Behavior
- Covers many topics
    - Internet use, telephones, computers, mobile devices, etc.
- Used by an organization to limit legal liability
    - someone is dismissed? These are well documented reasons why

**<u>Business Continuity</u>**
- Not everything foes according to plan
    - Disasters can cause disruption to the norm
- Rely on our computer systems
    - Tech is pervasive
- needs to be alternative
    - Manual transactions
    - Paper reciepts
    - Phone calls for transaction approval
- must be tested and documented before problem

**<u>Disaster Recover Plan</u>**
- If disaster happens IT is ready
- Part of business contrinuity plan
- Disasters are many and varied
- Comprehensive plan needed

**<u>Incident Response Roles</u>**
- Incident Response Team
    - Specialized group
- IT security management
- Compliance officers
- Technical staff, user community

**<u>NIST SP800-61</u>**
- Computer Security Incident Handling Guide
- Incident Response Lifecycle
1. Preparation
2. Detection and Analysis
3. Containment, Eradication, Recovery
4. Post Incident Activity

**<u>Software Development Lifecycle (SDLC)</u>**
- Systems or app dev lifecycle
- many ways to get from idea to app
    - Many moving parts, customer requirements
    - keep process schedule
- No "best way"
    - Helps to have framework, many options
    - Agile, Waterfall

**<u>Change Management</u>**
- how to make a change
    - Upgrade software, change firewall config, modify switch ports
- One of most common risks in enterprise
    - Occurs frequently
- Often overlooked or ignored
- Have clear policies
    - Frequency, duration, installation processes
    - Fallback procedures
- Sometimes extremely difficult to implement
- hard to change organization culture



### 5.1 - Security Standards
- Formal definition for using security technologies and processes
- Complete documentation reduces security risk
- Everyone understands expectations
- may be written in house
    - Requirements may be unique
- Many standardsa are already available
    - ISO (International Organization for Standardization)
    - NIST (National Institute of Standards and Technology)

**<u>Password</u>**
- What makes a good password
    - Every organization has their own requirements
    - Create formal password complexity policy
- Define acceptable authentication methods
    - no local accounts, only LDAP to AD database, etc.
    - Create policies for secure password resets
- Other policies
    - Frequency, string, managers

**<u>Access Control</u>**
- how does an organization control access to datat
    - Determine which info at which time
    - Under which circumstances
- Define which access control types can be used
    - No discretionary, mandatory only, etc.
- Determine how user gets access
- Document how access may be removed

**<u>Physical Security</u>**
- Rules and policies regarding physical security controls
    - Doors, building access, property security
- Granting physical access
    - Different for employees vs. visitors
- Define specific physical security systems
    - Electronic door locks, ongoing monitoring, motion detection, etc.
- Additional security concerns
    - mandatory escorts, off-boarding, etc.

**<u>Encryption</u>**
- Define specific standards for encrypting and securing data
    - All things cryptographic
    - can include implementation standards
- Password storage
    - methods and techniques (hash, salted, algorithm)
- Data encryption minimums
    - Algo for data in use, transit, and at rest
    - Probably different for each state


### 5.1 - Security Procedures
**<u>Change Management</u>**
- Formal process for managing change
    - Avoid downtime, confusion, mistakes
- Nothing changes without the process
    - Determine scope of the change
    - Analyze risk, create plans, get end-user approval
    - Present cahnge
    - have backout plan
    - Document change

**<u>Onboarding</u>**
- bring new person into org
- IT agreements signed
- Create accounts
    - Proper gorups and departments
- Provide required IT hardware
    - Preconfiguerd and ready to go

**<u>Offboarding</u>**
- Process should be pre-planned
- what happens to hardware? data?
- Account info deactivated

**<u>Playbooks</u>**
- Conditional steps to follow
    - Investigate data breach
    - Recover from ransomware
- Step-by-step set of processes and procedures
    - Manual checklist
    - Can be used to create automated activities
- Often integrated into SOAR platform
    - Security orchestration, automation, response
    - Integrate third party tools and data sources
    - make security teams more effective

**<u>Monitoring and Revision</u>**
- IT security is constantly changing
    - processes and procedures also must change
- update to security posture
    - Tighter change control, additional playbooks
- Change to individual procedure
    - Update playbooks, include additional checks
- New security concerns

**<u>Governance Structures</u>**
- Boards, panel
- Committees
    - Take direction from board
    - Compile next steps
- Government entitieis
    - Legal, administrative requirements
    - open to public
- Centralized / Decentralized
    - Source of processes and procedures
    - Spread or don't spread decision making


### 5.1 - Security Considerations
**<u>Regulatory</u>**
- Regulations are often mandated
    - Security processes, foundational considerations
    - Logging, data storage
- Sarbanes-Oxley act
    - Public company accounting reform and investor protection act 2002
- health insuraance portability and accountability act (HIPAA)

**<u>Legal</u>**
- Security Team often tasked with legal responsibilities
    - Reporting illegal activity
    - Holding data required for legal proceedings
- Security breach notifications
    - Legal requirements in many jurisdictions
- Cloud computing can make things challenging
    - Data moving between jurisdictions

**<u>Industry</u>**
- May requires specific considerations
- Electrical power and public utilites
    - isolated and protected system controls
- medical
    - Highly secure data storage and access logs
- Data encryption and protection

**<u>Geographical Security</u>**
- Local / Regional
- national
    - Different considerations for each
- Global
